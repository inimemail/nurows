Changed branch/field
- IP pool UI/backend: removed lease and cooldown configuration and hidden lease management view.
- Incident success path: allocated IP assets are deleted and removed from every pool reference.
- Incident failure path: allocated assets remain available after internal locks are released.
- IP usage history: processing, consumed, failed, and rolled-back attempts remain searchable after asset deletion.
- Probe target checks: Ping is the default, TCP port is shown only for TCPing, all assigned probes complete a round, any success wins, and all failures trigger the failure threshold.
- Incident without an available replacement IP: status remains waiting_for_ip and is retried only after an eligible asset is added or becomes available.
- Waiting incident recovery: adding an IP requests an immediate target recheck; a recovered target closes the incident without consuming an IP.
- Replacement IP preflight: each allocated IP is Ping-checked three times; unusable addresses are discarded, audited, recorded, and replaced from the pool.
- Legacy no-IP failures are normalized to waiting_for_ip so they no longer generate repeated execution failures.
- Incident cleanup: individual deletion and bulk cleanup remove idle/history rows and associated idle leases while preserving running automation, DNS, verification, and rollback work.
- Automation progress log: expanded per-host output uses the auto-scroll renderer so the inner log scrollbar follows the newest output.
- Target/policy/DNS account/DNS binding rows: triple-click opens a copy dialog with identity fields cleared while reusable configuration is retained.
- Automation step ordering: each step has a drag handle; dropping before another step updates the draft array and numbering, and up/down controls cover touch devices.
- Probe target check window: every interval runs three rounds with three Ping/TCP attempts per round; the first success ends the check and only nine failures produce a failed observation.
- Probe aggregation: any assigned probe success keeps the target healthy; all assigned probes must submit fresh complete 3x3 failures before failover is eligible.
- Incident execution guard: target health is re-evaluated before allocation and immediately before automation/DNS side effects; recovery or incomplete evidence releases IP locks and stops execution.
- Waiting-IP recheck: all assigned probes must report after the recheck request, preventing old successes from being combined with new failures.
- Probe target UI: legacy consecutive failure/recovery fields are removed; 3x3 evidence and agent upgrade state are visible.
