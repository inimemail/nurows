# NuroSSH

一个带 Web 终端、批量命令执行、代理管理的轻量控制台，现已支持 SQLite 单文件持久化，并提供 Docker / Docker Compose / install.sh 一键部署。

## 部署方式

### 1. 直接用 Docker Compose

1. 复制环境变量模板：
   - `cp .env.example .env`
2. 按需修改 `.env`：
   - `PORT`
   - `HOST`
   - `SQLITE_DB_PATH`
3. 启动服务：
   - `docker compose up -d --build`
4. 打开：
   - `http://<你的IP>:<PORT>/`

默认数据目录：
- `./data`

默认 SQLite 文件：
- `./data/app.db`

### 2. 用 install.sh 一键安装到服务器

适合想做成固定目录、后续通过管理脚本升级/备份/恢复的场景。

1. 直接执行：
   - `bash <(curl -fsSL https://raw.githubusercontent.com/inimemail/nurows/main/install.sh)`
2. 或者先上传项目后再执行：
   - `bash install.sh`
3. 按提示输入：
   - 安装路径
   - 对外端口
4. 脚本会自动：
   - 复制应用到 `/opt/nurossh` 或你指定的目录
   - 生成 `.env`
   - 启动 `docker compose`
   - 挂载数据目录

## 管理命令

安装完成后可使用：

- `bash install.sh install`
- `bash install.sh upgrade`
- `bash install.sh stop`
- `bash install.sh restart`
- `bash install.sh status`
- `bash install.sh logs`
- `bash install.sh backup`
- `bash install.sh restore`
- `bash install.sh uninstall`

如果已经安装到了目标目录，也可以用：

- `/opt/nurossh/manage.sh`

## 存储说明

当前后端默认使用 SQLite：

- 数据库文件：`data/app.db`
- 启动时会自动迁移旧数据：
  - `data/state.json`
  - `data/auth.json`
  - `data/secret.key`

迁移完成后，后续读写都走 SQLite。

自动化执行、DNS 守护检查、故障事件、IP 使用、DNS 变更和审计历史默认保留 7 天，服务启动时及每小时自动清理。现有条数上限继续生效，达到上限可能提前淘汰历史。没有有效时间的旧记录从首次清理检查开始保留 7 天。

可在「设置 → 一键清空所有历史记录」手动清理，确认后不可恢复，已删除故障历史对应的回滚入口也会移除。执行中、等待处理、仍持有有效 IP 锁及故障恢复依赖的记录会保留；配置、资产、远端 DNS 记录和当前终端不会被删除。SSH 输出仍使用原有的会话保留规则，不属于此处的历史记录清理范围。

六类记录也各有独立的「清理全部」：自动化页面的「执行记录」、DNS 守护的「检查记录」、故障事件、IP 池的「使用记录」、DNS 的「变更记录」、设置中的「审计记录」。每个入口只清理该类别的全部历史（包括未显示的页和未匹配筛选的记录），经确认后执行，保留规则与全局清理一致。单独清理 DNS 变更、IP 使用或自动化记录时，仍被故障事件引用的回滚依赖会保留。新增记录窗口按需分页读取，不进行后台轮询。

探针编辑页可单独选择「上下线通知机器人」，新旧探针默认均不选择、不发送通知。选择后，首次上线、超过 90 秒无心跳离线、恢复上线时，发送到所选机器人的接收 ID；每 10 秒检查离线状态，重复心跳不重复通知。未接入、已停用的探针不报离线，通知不影响探针检查和心跳处理。

每条 DNS 守护规则也可独立选择 TG 通知机器人；新建及原有未配置通知的任务默认不选，复制规则时保留原规则勾选的机器人，不再向全部机器人广播。仅在删除不健康 IP 后向所选机器人发送通知，包含剩余活动 IP 数量；正常检查不通知。

DNS 守护的「备用池补位」支持「故障补位」（默认，沿用原规则）和「补满指定数量」。补满目标不得超过活动解析上限；例如目标 50、已有 49 个健康 IP 时只补 1 个。先处理来源域名，再从已选备用池按顺序补足健康 IP；库存不足先写入通过检查的部分，保留缺口，补货后只唤醒关联且缺 IP 的空闲任务。后续检查按最新健康数量重新计算缺口；调低目标不主动删除健康 IP。任一负责探针成功即可使用候选，全部负责探针完成所有失败轮次才认定失败，候选检查保持并行并受现有并发上限约束。

备用池页面明确区分「DNS 守护取用：跟随守护设置」与「故障切换取用：每次一个／指定数量／全部」。固定或随机选择顺序仍共用，同一备用池可供不同守护按各自目标取用；已被守护检查占用的候选不会同时分配给其他守护或故障切换。

每条 DNS 守护可选择「按顺序取用」（默认）或「均衡取用」。均衡模式按域名当前仍健康的 IP 来源池计数，优先从数量少的池补入，尽量平衡补位后的总占比：50 个池来源 IP、2 个池尽量达到 25/25，3 个池尽量达到 17/17/16。某池库存不足或检查失败时由其他池补足；关闭自动调整时，已满额不主动删除健康 IP 来强制均分。来源池归属随当前 IP 持久保存，不依赖历史记录保留期限；旧 IP 仅从现存成功使用记录恢复归属，无法确认的手工或域名来源 IP 不猜测归属。数量相同时按持久化轮换顺序取用；候选检查保持并行，数量足够即完成，不为严格均分等待慢探针。池内固定或随机选择顺序仍按各池设置。

选择均衡模式时默认开启「自动调整已有 IP」，可手动关闭。升级时已有均衡任务也会一次性开启，不必逐条编辑；此后手动关闭会持久保存，重启不会再次开启。原本停用的守护仍保持停用，正在写入确认的任务保留原进度。新增关联池后，守护先检查占比不足池的候选 IP，再替换远程记录；确认远程结果一致后，才将换出的健康 IP 退回原备用池，并写入「已退回原池」使用记录。只调整来源明确、仍关联且启用的池所提供的 IP，不移动手工/未知来源或 DDNS 来源 IP。故障补位优先；空池、候选失败或库存不足只影响可调整的数量，旧健康 IP 不会因此被清空，后续有库存再继续。多个池允许相差 1 个的余数，不反复挪动。写入超时或重启后保留两侧 IP 占用，按检查间隔（至少 10 秒）确认远程结果；确认前不退池、不重复消耗，并暂时阻止该守护的手工修改。若远程结果与调整前后均不一致，会保留占用并显示错误，需核对服务商记录。其他守护不受该确认等待影响。

「自动调整间隔（分钟）」默认 30，可设置 1–1440 分钟。开启自动调整或更换关联池并保存后立即排队评估一次，之后从该次完成起计时；重启、普通编辑、日常健康检查和补充库存不会重置或绕过间隔。修改间隔按最近一次评估时间重新计算。自动调整与健康检查共用同一任务队列，不并行执行两套检查：故障删除、缺口补位和补满始终优先，按原健康检查周期均衡补充，不等待调整间隔；本轮有故障或缺口时只补位，已有健康 IP 的调整留到下次定时评估。已均衡时不换 IP，空池或部分调整后等下次评估再尝试。沿用全局并发限制，不新增逐任务定时器；等待远程确认时停止无用的探针检查，普通健康检查不加载备用资产、租约或使用历史。

编辑或新建备用池时，保存会跳过已被后台消耗或删除的旧资产 ID，并显示跳过数量；明确重新输入的 IP 地址仍可作为新资产加入，不会因弹窗内过期的关联阻挡保存。

## 续费管理

每条记录的「服务器续费通知」默认勾选，已有未设置开关的记录也默认开启，使用提醒设置中的默认机器人。取消勾选只停止这条记录的通知；重新开启保留已发送节点，避免重复提醒。可展开「单独指定通知机器人」覆盖默认选择。复制记录保留其通知开关和机器人选择；未配置任何机器人时不会发送。

服务器名称和非空 IP / 域名分别要求唯一，前端即时提示、后端保存时再次校验；编辑时排除当前记录。名称忽略首尾空格、大小写及全半角差异；域名忽略大小写、末尾点并统一国际化域名，IPv6 等价写法也视为同一地址。地址为空的记录不互相冲突，已有重复记录不会被自动删除。

入口在顶栏「Telegram」之前。服务器名称必填；IP / 域名、金额、币种、到期日期和备注可选。金额支持 0，日期为空显示「未知日期」、排在最后且不提醒。已过期记录优先显示（最近过期在前），其后按到期日升序排列。可搜索名称、地址、备注，按状态筛选，编辑、选择删除或确认删除全部；每页最多显示 50 条。三连点记录空白区域或「更多 → 复制」创建副本，保留金额、日期、备注及通知选择，清空名称和地址。

「全部删除」旁的设置按钮配置默认 TG 通知机器人及统一提醒节点，默认提前 7、3、1 天及到期当天，北京时间 09:00；节点和时间均可修改，全部取消节点则暂停通知。默认机器人支持多选，初始为空；记录未单独选择机器人时跟随设置，已单独选择的优先使用自身配置。列表显示默认通知机器人，编辑页显示当前通知选择。默认及单独选择均为空时不通知；发送给所选机器人配置的接收 ID，停用整个机器人会停止通知。管理菜单权限不影响通知选择。新增临近到期记录、修改到期日或新增通知机器人时立即提醒当前阶段一次，不补发多个历史节点；过期后不每天重复提醒。更换默认机器人不会清空已发送状态，普通编辑或重新选回相同机器人不会重复发送同一节点。

后台只有一个分钟级调度器，按机器人及接收人合并消息，分段发送并限制单轮批次，不连接服务器、不解析域名、不占用探针。已成功提醒状态持久保存，重启和普通编辑不会重复发送；修改到期日期开始新的提醒周期。TG 明确拒绝时最多尝试 3 次、间隔至少 5 分钟；发送超时或进程中断无法确认结果时，为避免重复提醒，不重发同一节点，列表显示提示，下一节点仍可提醒。停机错过节点时，仅补当前仍适用的一次提醒，不追溯已过期记录。

续费记录及提醒状态属于长期配置，不受历史记录 7 天清理影响。删除只影响续费管理，不会删除服务器、守护或远程资源。此功能不自动付款或执行续费操作。

## Telegram 管理菜单

发送 `/menu` 打开主菜单：系统总览、故障事件、DNS 守护、动态 IP 守护、探针与检查、IP 资产与备用池、解析管理、自动化任务。列表每页 8 条，支持搜索、异常筛选、刷新和返回；刷新及翻页更新当前消息。DNS 守护支持检查、管理 IP、来源状态及检查记录；动态 IP 守护支持检查、确认换 IP、启停和执行记录。自动化任务和执行记录仅显示当前机器人获准使用的任务。

在网页「Telegram → 编辑机器人 → TG 可用管理功能」分别选择各项权限。旧版「探针」迁移为「探针节点 + DNS 守护」，旧版「备用池」迁移为「备用池 + IP 资产」，其他新增功能需单独勾选；全部取消表示关闭所有管理功能。管理权限与各任务的通知接收选择独立，关闭管理入口不会取消已配置的通知。关闭整个机器人则停止该机器人的管理和通知。

删除、替换 IP、启停、换 IP、故障执行及回滚需要确认。输入和确认按机器人、聊天、用户隔离，10 分钟过期；返回菜单或取消后旧确认失效。旧消息按钮和最终执行都会重新检查权限。批准者只能确认故障执行及回滚，不能清理事件；清理已结束事件会保留仍执行、持有 IP 锁或有待恢复 DNS 变更的记录。

管理 IP 默认查看已保存记录，不因打开菜单读取服务商；点击「读取远程」才同步。DNS 写入前核对确认时的记录，发生变化则要求重新读取。普通解析绑定至少保留一条记录，有动态来源的绑定需在网页编辑。慢操作在后台处理，最多同时 4 个、另有 32 个等候名额，同一资源重复操作会拦截，不会阻塞其他菜单。

可选配置 `PUBLIC_APP_URL=https://panel.example.com`，重启后 TG 的「打开网页编辑」会定位相应模块和规则，仍需正常登录。未配置时显示网页操作指引。网页权限选择沿用桌面双列、移动端单列布局。

## 动态 IP 守护

入口在「探针管理 → DNS 守护」后面的「动态 IP 守护」。填写一台 VPS 对应的 DDNS 域名、换 IP API 命令并选择探针；支持 A / AAAA、Ping / TCP。任意探针任意一次成功即正常，全部负责探针完成配置的全部失败轮次才触发换 IP。轮次在一次检查中连续进行，不按检查间隔逐轮等待。探针离线、回报不完整或 DNS 查询失败不会直接触发换 IP；域名同时返回多个地址时提示查询异常，不猜测目标。

API 命令在面板所在 Linux 环境本地异步执行，不通过 SSH 连接目标。Docker 镜像包含 bash、curl、GNU coreutils 和 CA 证书；直接部署到 Debian 时须安装 `bash curl coreutils ca-certificates`。命令应通过退出码表达提交结果（例如 curl 使用 `--fail --max-time 60`）；HTTP 200 中的业务失败需由所填命令自行判定。仅保存配置不会执行命令，但启用后确认目标故障会自动执行。命令以面板进程的系统权限运行，不继承面板的其他环境密钥，命令本身加密保存，查看命令需登录；命令输出可能包含服务商返回的信息，仅保存最近 8192 字符且不发送到 Telegram。

默认检查间隔 30 秒、3 轮 × 每轮 3 次、每轮超时 5 秒。换 IP 请求提交后，每 5 秒查询 DDNS；等待 300 秒仍成功解析到旧 IP 则重提，等待时间和查询间隔可自定义，等待超时为 0 时持续等待。新 IP 任一探针一次成功即完成；全部探针完整失败后继续换。API 命令默认超时 90 秒，超时或退出异常先确认地址变化，不立即重发。面板重启后保留等待流程，旧命令的硬超时期限到达前不重复提交。

每日上限默认 5 次，0 表示不限，按北京时间零点重置。实际发起的手动、自动、超时重试及命令失败均消耗一次尝试；达到上限后仍会验证已经出现的新 IP，次日重新确认后继续。冷却时间限制两次提交的最短间隔。等待时允许编辑和停用，正在执行 API 命令时禁止编辑或删除；修改目标会结束旧目标等待流程，已提交服务商的请求无法撤销。

解析准备最多并发 10 个，活动探针检查最多 10 个，API 命令独立最多并发 4 个。等待 API 空位不占用探针检查名额，排队失败证据超过 30 秒会重新检查。重复点击检查不会打断当前轮次。正常检查成功即结束，无常规通知；换 IP 完成、等待超时重试、命令异常、每日上限通知会去重。等待期间相同解析结果不重复落库，普通状态更新仅复制当前任务，不复制无关历史（底层仍使用现有整份 JSON 持久化）。页面仅轮询当前功能状态，后台标签页暂停读取，倒计时独立更新，不带动列表和表单每秒重绘。

执行命令期间也可以停用，停止后续检查和重试；已经提交的服务商请求无法撤回，命令结果仍会保存。再次启用时重新确认当前状态。动态 IP 守护执行记录同样保留 7 天，最多保留 1000 条已完成记录；每个任务可单独查看分页记录，顶部「执行记录」中可清理该类别，也纳入全局清理，未完成流程自动保留。

## 安全策略

Docker 运行配置已经做了几项基础收敛：

- 容器内默认非 root 用户运行
- `cap_drop: ALL`
- `no-new-privileges:true`
- 数据单独挂载到 `./data`
- `/tmp` 使用 `tmpfs`

终端和命令中心的 WebSocket 会核验登录会话与浏览器 Origin。退出登录立即撤销该会话的全部 WebSocket；修改账号信息会撤销所有旧会话连接，后台自动化任务继续运行。会话过期后拒绝输入和输出并关闭连接，畸形 Cookie 或握手请求不会退出面板进程。

浏览器终端和命令中心连接前，会通过已登录的同源 HTTP 请求领取一次性连接凭证，绑定当前登录会话、浏览器 Origin 和终端通道，30 秒过期；反代把 HTTPS 转为 HTTP、改写后端 Host 或使用非标准外网端口时，不再仅因后端地址推断错误拒绝正常连接。凭证通过 WebSocket 子协议传递，不放在 URL 中；退出登录、跨站请求和重复使用均会被拒绝。前后端需同时更新，部署后刷新浏览器。

Nginx 仍需正常转发 WebSocket Upgrade 和浏览器的 Origin、Sec-WebSocket-Protocol，HTTP 请求的 Fetch Metadata 也应保留。通常应保留 `Host` 并覆盖设置 `X-Forwarded-Proto`（Nginx 对应 `$http_host` 和 `$scheme`）。旧客户端或未提供 Fetch Metadata 的浏览器继续使用严格来源校验，需要不同公开域名时可配置 `ALLOWED_ORIGINS=https://panel.example.com`，多个完整来源用逗号分隔，不支持通配符。不带 Origin 的连接会被拒绝。此校验不影响探针 HTTP 接口。
