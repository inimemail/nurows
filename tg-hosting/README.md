# TG 托管

在面板「易支付」后打开 **TG 托管**。每个账号使用服务器上的独立 Chromium 官方 Telegram 网页，通过已登录面板的 WebSocket 传输画面；不是 iframe，也不依赖用户电脑的浏览器登录数据。

## 部署与使用

使用管理脚本菜单 **2 升级服务** 更新面板，然后菜单 **11 TG 托管组件** 安装可选组件。也可运行 `bash /opt/nurossh/manage.sh tg-hosting`。不启用时不下载或启动 Chromium。

添加账号后点击「打开」，验证面板密码，在窗口中的官方网页自行扫码或输入手机号登录。无需提供 Telegram API ID/hash。账号默认关闭窗口后仍运行；「自动休眠」模式关闭窗口后停止浏览器并保存登录配置。休眠期间不接收消息，再次打开时由官方网页补同步。休眠不调用退出登录。

账号支持名称、分组、备注、搜索、编辑、休眠、保存快照、单独或全部删除。删除均须二次确认，只删除本地托管资料；在 Telegram 中撤销设备请使用官方客户端。默认后台保持、休眠均不能保证官方会话永不失效：官方撤销、账号限制或网页要求重登时仍须重新验证。程序不会因启动失败自动清空登录配置。

运行窗口默认接近整个页面，账号名与工具按钮共用一栏；支持全屏、动态分辨率、触摸操作、中文输入与粘贴、复制远程选中文字。远程分辨率按窗口比例调整，最大 1440×900；大屏由 noVNC 本地缩放显示，鼠标/触摸按缩放比例换算，避免 4K 全屏增加数倍服务器渲染开销。画面上限 30 次更新/秒，降低压缩等级以减少编码 CPU；慢连接逐段暂停和恢复读取，保留硬缓冲上限，不丢弃 VNC 字节流。手机端可以使用「输入与粘贴」，先点远程网页输入框，再写入文字。下载、摄像头、麦克风及任意外部网页被禁用；此功能定位于消息和账号管理。

## 资源与兼容性

需要 Linux Docker Engine（API 1.41+）和 Compose，amd64/arm64，以及宿主机允许非特权用户命名空间。Chromium 保留内部 sandbox；不支持时显示启动异常，禁止用 `--no-sandbox` 绕过。可在宿主机检查内核 user namespace、AppArmor 和容器运行时限制。

默认同时运行最多 2 个账号，单账号最高 1024 MB / 1 核，设置可调整。新账号按启动时内存余量分配 512 MB 起的实际硬限额，按 128 MB 递增，不超过设置的上限；账号行显示实际限额。已有运行账号不降额、不重启，新设置在下次启动生效。启动串行排队，保留至少 384 MB 或宿主机总内存 20% 中较大的余量，同时计入其他浏览器在各自硬限额内还可能增长的内存；资源不足时不抢占已有账号。休眠回收浏览器容器和独立网络，释放该账号的 CPU、内存及网络地址；保留登录目录和加密快照，并让等待资源的账号重新检查预算。大量账号同时运行还需为 Docker 配置足够的地址池。后台保持账号仍需运行完整浏览器，会随聊天量和网页版本占用不同资源。约 2 GB 内存且剩余约 1 GB 的机器可以尝试运行一个 512 MB 账号；大型聊天记录、媒体或多个同时运行账号仍建议至少 4 GB 并按实际负载扩容。

支持保存多个独立账号；同时运行上限可设为 1–50，实际启动数量还受宿主机资源预算约束。内存上限对每个账号的整个容器生效，包括 Chromium 子进程、画面服务及内存临时文件；禁止额外使用 swap。单账号上限可设为 512–8192 MB。启动前验证 Docker/内核支持内存、swap、CPU 和进程数限额，并核对新容器的实际限额配置；不支持时保留资料并暂停新启动。单个账号的检查失败不会跳过其他账号的健康检查，状态无法确认时保留其资源名额，避免超额启动。

只有打开画面才传输图像；列表按页返回，搜索延迟合并。打开账号画面时暂停遮挡在背后的列表轮询，仅检查当前账号状态，关闭画面后立即恢复列表刷新。页面隐藏时暂停画面传输和轮询，回到前台自动重连，不退出后台账号。浏览器初始画面为 1024×768，打开后随窗口调整；关闭不需要的 GPU 加速、扩展和 Chrome 后台服务，减少渲染进程及缓存开销，保留 Chromium sandbox、Telegram 连接和持久化配置。独立 runner 对 Docker/归档执行限额，不在面板进程中压缩文件或运行浏览器。运行容器健康检查每轮批量查询，资源容量短期缓存；状态读取不等待 Docker 资源查询或归档。只在新账号申请启动时读取已有浏览器的单次内存统计，缓存 5 秒、并发最多 4 个、整轮最多约 2 秒；统计失败时按完整限额保留增长预算，普通列表轮询不采集逐账号统计。启动前检查内存和两个持久目录的磁盘空间；资源读取失败时暂停新启动。浏览器合计 CPU 预算最多使用宿主机 75%，单账号实际 CPU 上限会按剩余预算降低。资源不足按退避间隔重查；运行期间磁盘空间接近保留阈值时，正常停止浏览器并保留当前目录和旧快照，清理空间后自动恢复；资源读取失败不会据此停止已有账号。启动失败、OOM 最多自动重试 3 次，随后保留资料等待手动重试，避免反复重启。单账号运行数据默认管理上限 5 GB，配置及快照仍保留 10 万文件的安全限制。

账号存储上限在「设置」中调整为 1–20 GB，旧配置默认采用 5 GB。列表显示运行目录用量和独立快照大小，脚本备份不计入单账号运行数据。统计使用文件逻辑大小（GB 按 1024³ 字节计算）；恢复后尚未展开的账号只占加密快照空间，展开后再统计运行目录。运行账号约每 5 分钟统计一次，休眠/排队账号约每 30 分钟，超限账号约每 5 分钟复查；所有扫描串行、运行账号优先、队列繁忙时顺延，每秒最多开始一个账号的检查。单次扫描最多 10 万目录项、30 秒，遇到文件变化或故障保留资料，不阻塞缓存状态读取。启动前单独检查用量，列表刷新不会触发目录扫描。

每个账号按 24 小时周期错峰清理明确列出的 Chromium 缓存，维护时间独立保存在配置目录外，组件重启不会重置周期。首次启用先记录时间，约 23–24 小时后首次例行清理；没有可清理缓存时不重启浏览器，正在查看时顺延至关闭画面后。达到 85% 且至少有 64 MB 可重建缓存时，也会安排清理，每账号最多每 30 分钟一次；正在查看时暂缓，达到上限则优先处理。清理前正常停止浏览器，清理后按原意图恢复，休眠账号不唤醒。达到上限时先尝试安全清理，仍超限则保持暂停，不循环启动。IndexedDB、Local Storage、Cookies、Sessions、Service Worker 和 Local State 数据不作为可删除缓存；媒体和认证可能混存，因此不支持一并清空这些数据。清理和备份排除使用精确缓存路径，保留其他位置的同名目录，清理拒绝符号链接。异常退出或无法确认清理结果时保持暂停、保留当前资料和旧快照；提高上限后重新检查。该上限是定期检查的管理阈值，可能短暂超出，避免用文件系统硬截断正在写入的登录数据库；宿主机剩余空间保护仍独立运行。

加密快照与恢复采用独立的 20 GB / 10 万文件安全上限，允许备份因运行阈值而暂停的账号；调低运行上限不会阻止抢救已有数据。生成新快照前，复用正常停止的时机清理安全缓存，不为清理额外重启账号、不再做一遍完整目录扫描；清理失败仍可继续备份，归档自身会排除缓存。清理不会删除 IndexedDB 等认证数据，也不调用退出登录。异常退出时不清理；已有完整快照时拒绝覆盖。未重新启动的休眠账号复用原快照。

归档逐文件读取属性、流式压缩/加密，及时释放已处理文件的归档元数据；恢复两遍顺序读取压缩包，先完成路径、类型及大小验证，再提取到独立目录，避免大量文件的元数据在内存中重复堆积。完整验证和剩余磁盘空间检查仍保留，单个辅助任务最多 15 分钟；原完整快照只在新快照成功后替换。恢复后仍须通过当前运行上限才能启动。

后台保持直接运行官方网页，由 Telegram 自身维持连接和断网重连；不定时刷新页面、不自动发送消息。浏览器每 30 秒做一次本地 VNC 服务检查，启动宽限后连续 3 次失败才判定不健康；runner 再确认后只重启该账号，并保留当前登录目录及旧快照，使用原有的退避和最多 3 次重试规则；连续健康运行 30 分钟后重置故障重试计数。归档容器不运行此检查。该检查只能判断浏览器服务，不能确认 Telegram 服务器仍认可登录。画面断开按 2/5/10/20/30 秒重连，最多连续 5 次；不唤醒或重启浏览器、不延长密码解锁时间，画面稳定连接 30 秒后重置重试计数。后台页面暂停画面重连，恢复前台后重新连接。休眠账号不运行官方网页，也不做在线保活；要保持连接请使用默认的后台保持模式。

## 数据、备份与恢复

- `tg-browser-data/<账号 UUID>/`：正在使用的完整浏览器配置，权限受限，持久化到宿主机；**运行配置本身没有落盘加密**，需要宿主机磁盘加密来保护被盗磁盘。
- `data/tg-hosted-snapshots/<UUID>.tar.gz.enc`：AES-256-GCM 加密快照，使用现有应用密钥派生的独立密钥；不会将密钥返回浏览器。
- 手动、定时、升级前备份共用原备份目录及保留最新 3 份规则。备份先协调 runner 停止浏览器，完成各账号快照，复制数据库和加密快照后按原状态恢复。期间画面会断开，需要重新连接。账号很多或数据大时备份更久，页面其他功能仍可使用。
- 恢复沿用管理脚本菜单 6，提供原备份及原 `secrets/master.key`。组件开启标记在备份的 `.env` 内；脚本自动重建组件。账号下次启动，在空目录中完整验证快照后解压，再打开官方网页。
- 恢复后默认「等待接管」，不会自动启动账号。先在旧机器停止 TG 托管，再到新面板确认接管；后台保持账号按最近运行顺序逐个排队恢复。每次恢复生成新的接管标记；普通升级/重启无需重新确认。不要把同一备份恢复到多台机器后同时运行同一账号。
- 长时间不打开面板不会清理账号、登录目录或加密快照；后台保持继续运行，休眠只停止浏览器。Telegram 官方的撤销设备、账号风控和会话有效期仍由官方决定，不能保证会话永久有效；建议保留其他官方客户端登录和手机号恢复方式。
- 已保存且未再次启动的休眠账号复用原快照，不反复压缩；从未打开的空账号不创建浏览器或归档容器。恢复前分别检查压缩文件和解压后的空间。损坏快照会拒绝启动，保留原文件，不自动新建空白浏览器。
- 浏览器 OOM 或强制结束时，不覆盖已有的完整快照；同时保留当前登录目录，重新打开并正常关闭后再更新快照。快照失败会显示错误，后台恢复运行不会掩盖该错误。
- 已创建的浏览器配置另有持久资料标记，随加密快照进入备份，主动删除账号时才删除。目录与快照均缺失时明确报错，不新建空白会话；旧账号的最近成功运行记录也用于这项保护。空归档无法覆盖旧快照，解压目标必须为空，已有目录不会被解压失败的清理逻辑删除。
- 浏览器打开前先持久写入活动标记，确认正常退出后才移除。托管组件重启后仍能识别上次未正常关闭的配置，避免将其覆盖到旧完整快照；不会为此回退或清空当前登录目录。
- 不把活动 Chromium 数据库直接打包。备份中存在托管账号但组件不可用时会明确失败，避免生成遗漏会话的“成功”备份。请先恢复组件再备份。
- 登录资料属于敏感数据。root、Docker 管理员或宿主机被入侵时，仍可能读取正在运行的会话。不要共享 master.key 或公开配置目录。

## 安全边界

管理脚本菜单 **8 完全卸载** 检测到账号登录目录、加密快照或资料保护标记时会拒绝卸载，防止把卸载等同于删除账号。须先在面板中主动删除对应托管账号；确认没有账号资料后，才会停止面板与组件，移除本实例残留容器、网络、Compose 卷并删除部署目录（含密钥及备份）。即使 runner 已崩溃，也按归属标签和配置目录挂载清理遗留资源；任何清理/停止失败都会保留部署目录。同一会话标识被其他部署使用或网络连接其他容器时拒绝清理。宿主机 Docker、共享镜像缓存和其他部署不删除。

面板正常登录外，打开/修改会话还需验证面板密码；解锁仅绑定当前登录会话，闲置 10 分钟锁定，最长 30 分钟重新验证。锁定停止画面访问，不退出后台账号。WebSocket 使用一次性连接凭证和内存中的解锁令牌，不放入 URL。账号一次只允许一个控制窗口。

独立 runner 挂载 Docker socket，具有很高的宿主机权限；主面板不挂载它，只通过私有 Unix socket 操作受限账号接口。每个浏览器独立容器、网络、持久目录、CPU/内存/PID 上限，不公开 VNC、调试或 Docker TCP 端口。浏览器进程不记录消息、二维码、验证码和剪贴板内容。Chromium 内部沙箱需要 user namespace 系统调用，因此浏览器容器放宽 Docker seccomp；仍保留非 root、drop ALL capabilities、no-new-privileges、只读根目录。宿主机及 Docker 管理权限必须受信任。
